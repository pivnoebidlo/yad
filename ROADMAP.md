# YAD — идеи на будущее

Состояние на v0.3.0 (14.11.2026). Пункты по убыванию пользы.

## В первую очередь

### 1. Прогнать на реальных файлах
Синтетические stage/prod проверены, но настоящие манифесты почти наверняка вскроют то, что тесты не ловят: Helm-шаблоны, огромные `ConfigMap`, нестандартные списки, необычные комментарии. Самый дешёвый способ найти реальные проблемы.

Что нужно: пара реальных папок окружений (секреты можно заменить).

### 2. Helm и Kustomize — ✅ рендер сделан (терпимый разбор шаблонов — нет)
В Helm-шаблоне `{{ .Values... }}` — не YAML, сейчас такой файл помечается «не разбирается».

Варианты, от простого к сложному:
- **values-файлы**: `values-stage.yaml` против `values-prod.yaml` — уже работает, это обычный YAML;
- **терпимый разбор шаблонов**: `{{ … }}` считается непрозрачным значением, остальное сравнивается семантически;
- **сравнение отрендеренного результата**: `helm template` / `kustomize build` для двух окружений, и дифф уже готовых манифестов. Скорее всего, главный реальный сценарий «stage против prod».

### 3. Перечитывать изменённые на диске файлы — ✅ сделано (после v0.3.0)
Сейчас, если файл поменяли в редакторе или через `git pull`, YAD об этом не знает.
- следить за открытыми файлами и папками;
- нет несохранённых правок → тихо перечитать;
- есть правки → спросить: перечитать / оставить своё.

Маленький объём работы, но без него легко потерять чужие изменения.

## Расширят применение

### 4. Сравнение с живым кластером
Файл против `kubectl get -o yaml`. Шум (`status`, `managedFields`, `uid`, `resourceVersion`, last-applied) уже игнорируется, так что это почти готово. Видно, кто руками поправил прод.

### 5. Режим командной строки для CI — ✅ сделано (`yad-cli`)
```
yad diff stage/ prod/ --semantic      # отчёт + код возврата
yad format --check manifests/         # неотформатированные файлы → ошибка
```
- пайплайн ловит расхождение окружений или неотформатированный манифест;
- сюда же pre-commit-хук «Формат».

### 6. Интеграция с git — ✅ difftool и `git diff` сделаны (mergetool / трёхстороннее слияние — нет)
- сравнение с `HEAD` или с другой веткой;
- регистрация как `git difftool` / `git mergetool`;
- трёхстороннее слияние (base / ours / theirs) для конфликтов в манифестах — заметный шаг вперёд по сравнению с Meld.

## Удобство и мелочи

### 7. `.yadignore` в репозитории
Правила игнорирования и настройки формата хранятся в проекте, а не в настройках каждого человека. У всех коллег одинаковое оформление.

### 8. Расшифровка `Secret`
Значения `data` показываются раскодированными из base64, иначе дифф бесполезен. Аккуратно: при сохранении значения снова кодируются, раскодированное нигде не остаётся.

### 9. Поиск и фильтр
По изменениям и по списку файлов, когда папки большие.

### 10. Автообновление и нотаризация
- автообновление: инфраструктура Tauri почти готова, нужен ключ подписи;
- нотаризация для macOS — когда появится аккаунт разработчика (уйдёт шаг с `xattr`).
